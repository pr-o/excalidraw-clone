### Approved design (verbatim)

> **1. Delete dead `CanvasBgDialog`** — `setOpenDialog("canvasBg")` is never called anywhere, so the dialog can never open. Delete `packages/ui/src/CanvasBgDialog.tsx` and `packages/ui/test/CanvasBgDialog.test.tsx`. Remove the two `CanvasBgDialog` / `CanvasBgDialogProps` exports from `packages/ui/src/index.ts`. In `apps/web/src/components/Dialogs.tsx` remove the `CanvasBgDialog` import, the `setCanvasBg` selector, and the `<CanvasBgDialog .../>` JSX block — **keep** the `canvasBg` selector (used by `exportScene`). Remove `| "canvasBg"` from the `DialogId` union in `apps/web/src/store/slices/dialog.ts`. Remove the `canvasBg` key from `apps/web/src/locales/en/common.json` and `apps/web/src/locales/ko/common.json`. **Keep `apps/web/src/store/slices/canvasBg.ts` entirely untouched** — `setCanvasBg` is still called by `apps/web/src/driver/hydration.ts:28` and the `#ffffff` value feeds renderer/export/thumbnails. Only test referencing it is its own file. No e2e references `canvas-bg`/`canvasBg`.
>
> **2. PropertiesPanel viewport overflow** — `packages/ui/src/PropertiesPanel.tsx`, the root `<aside>`: add `max-h-[calc(100vh-1.5rem)] overflow-y-auto` to its className. A selected arrow makes the panel ~790px tall with no scroll, so lower controls are unreachable under ~800px. The wrapper in `apps/web/src/components/App.tsx` stays as-is.
>
> **3. Collapsed Layers/Library panels → floating buttons** — the collapsed panels currently render a full-height opaque `w-10` `bg-panel` strip that paints over the hamburger menu and the properties panel. In `packages/ui/src/LayersPanel.tsx`, when `!open` render ONLY the toggle button as a small floating control (`fixed left-3 top-16 z-30 flex h-9 w-9 items-center justify-center rounded-lg bg-panel shadow hover:bg-panel-hover`); when `open` render the panel exactly as today. `packages/ui/src/LibraryPanel.tsx` symmetric — collapsed button at `fixed right-3 bottom-16 z-30`, open state unchanged. Both: `data-testid`, `aria-label`, and `aria-expanded={open}` MUST remain on the button in BOTH states; the chevron glyph stays (`open ? "‹" : "›"` for layers, `open ? "›" : "‹"` for library). In `apps/web/src/components/App.tsx` change the hamburger-menu wrapper `<div className="absolute left-3 top-3 z-30">` to `z-40` so its dropdown sits above the collapsed layers button.
>
> **4. Library panel polish** — `packages/ui/src/LibraryPanel.tsx`: the `ItemTile` thumbnail `<button>` (with `dangerouslySetInnerHTML`) gets `overflow-hidden [&>svg]:h-full [&>svg]:w-full` so injected template SVGs stay inside the `h-20` tile. Change `library.import` value from `"Import library…"` to `"Import"` and `library.export` from `"Export library"` to `"Export"` in BOTH `en/common.json` and `ko/common.json` (Korean equivalents: `"가져오기"` / `"내보내기"`). These keys are used only for these two buttons. Adding `title=` is optional — the shorter label alone is fine.
>
> **5. Next.js dev indicator** — `apps/web/next.config.ts`: add `devIndicators: false` so the dev-only "N" badge stops overlapping the Pages tab bar. If typecheck/next rejects the key, drop this item silently (dev-only, optional).
